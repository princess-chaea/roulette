# 카메라 모션 경품 룰렛 — 구현 계획 v0.3

작성일: 2026-11-09
상태: 계획 초안. 앱 코드·모션 인식·배포는 아직 구현하지 않음.

## 1. 목표와 범위

운영자가 경품과 룰렛 조각을 설계하고, 참가자 이름을 입력한 뒤 카메라 앞에서 안내 동작을 따라 하거나 룰렛을 돌리는 손동작으로 경품 룰렛을 돌리는 웹앱을 만든다.
경품명이 적힌 원판 전체가 실제로 회전하고, 고정된 포인터 아래에서 멈춘 조각을 결과로 표시한다.

사용자가 요청한 기능:
- 등수별 상품명과 상품 개수 입력으로 룰렛 자동 구성.
- 색상과 조각 크기 수동 조절은 고급 설정 후보로 유지.
- 추첨 대상 이름 입력.
- 설계 화면에서 추첨 화면으로 이동.
- 카메라 화면에 동작 예시와 실시간 인식 상태 표시.
- 안내 동작 따라 하기 또는 룰렛 돌리는 손동작을 완성하면 추첨 시작.
- 숨겨진 운영자 조작으로 극적인 1등 당첨 연출.

초안의 해석과 제안:
- '당첨자 적기'는 추첨 대상 이름을 미리 입력하는 것으로 해석한다. 추첨 이후 이름과 경품을 함께 기록한다.
- 첫 버전은 한 사람씩 진행한다. 명단을 별도로 무작위 추첨하는 기능은 후속 범위다.
- 기본 모드는 남은 상품 개수에 비례해 조각 크기와 확률을 자동 계산한다.
- 한 등수를 하나의 조각으로 표시하고, 같은 등수 상품을 개수만큼 작은 칸으로 반복하지 않는다.
- 첫 버전에서는 개수 기반 자동 배분을 우선 구현한다. 크기 수동 조절은 별도 확률 모드가 필요하므로 후속 고급 기능으로 둔다.
- 숨겨진 조작은 연출 모드의 운영자 컨트롤로 제공한다. 일반 추첨과 연출 기록은 구분한다.
- 초기에는 로그인과 서버 없이 한 기기에서 설계·진행·기록을 다루는 방식으로 계획한다.
- 위 해석들은 구현 전 화면 초안 검토에서 수정할 수 있는 제안이다.

## 2. 페이지와 화면 구성

### A. 룰렛 설계 /setup

큰 화면:
- 상단: 행사 제목, 설정 저장/불러오기, '추첨 화면으로' 버튼.
- 왼쪽: 실시간 룰렛 미리보기.
- 오른쪽: 등수별 상품 입력 표와 행 추가/삭제.
- 하단: 참가자 이름/명단, 진행 옵션.

기본 입력 표:

| 등수 | 상품명 | 상품 개수 |
| --- | --- | --- |
| 1등 | 블루투스 스피커 | 1 |
| 2등 | 문구 세트 | 3 |
| 3등 | 간식 꾸러미 | 6 |

- 운영자가 입력할 필수 항목은 등수, 상품명, 상품 개수.
- 색상, 조각 각도, 확률, 총 상품 수는 자동 생성.
- 등수별 행 추가·삭제·순서 변경 가능.
- 같은 상품명을 여러 등수에 사용할 수 있으나 각 행은 독립된 상품 묶음과 재고로 취급.
- 고급 설정에는 우선 색상 변경을 제공. 수동 크기 변경은 후속 별도 확률 모드로 설계.
- 참가자 이름은 추첨 화면에서도 한 명씩 바로 입력 가능.

검증:
- 유효한 상품 행이 하나 이상이면 진행 가능.
- 빈 상품명, 중복 등수, 음수/소수 수량은 안내.
- 신규 행사 상품 개수는 양의 정수로 입력. 무제한 옵션은 기본 모드에 두지 않음.
- 1등은 등수 값으로 식별하고 중복 1등 행은 허용하지 않음.
- 초기 총 수량과 현재 남은 수량은 구분하여 보존.
- 작은 조각과 긴 상품명은 미리보기 가독성 안내와 전체 상품 목록으로 보완.
- 꽝은 자동 추가하지 않음. 참가자보다 상품이 적으면 재고 종료 안내. 꽝 기능은 후속 선택 사항.

### B. 경품 추첨 /draw

- 중앙: 화면의 중심을 차지하는 큰 룰렛, 상단 고정 포인터.
- 상단: 행사명과 현재 참가자 이름.
- 룰렛 옆: 동작을 확인하기 충분한 크기의 거울형 카메라 화면과 동작 안내 카드.
- 카메라 위에 감지된 손/팔 위치, 따라 할 동작 윤곽, 진행 게이지 표시.
- PC에서는 룰렛과 카메라를 나란히 배치하고 모바일에서는 위아래로 배치.
- 하단: 수동 시작, 소리 켜기/끄기, 다음 참가자.
- 당첨 후: 이름·경품·축하 효과와 결과 확정/다음 참가자 버튼.
- PC/프로젝터는 가로형 무대, 모바일은 세로형 배치.
- 화면 크기에 맞춰 영역을 재배치하고 핵심 입력·결과를 숨기지 않는다.

진행 흐름:
1. 현재 참가자를 선택하거나 이름을 입력.
2. 카메라에서 참가자와 손 위치를 확인하고 선택된 동작 예시 표시.
3. 동작 따라 하기/돌리기 → 인식 진행 표시 → 성공 피드백 → 회전 → 감속 → 정지.
4. 포인터가 가리키는 경품을 결과로 표시.
5. 결과 기록과 재고를 한 번만 반영하고 다음 참가자로 이동.

### C. 당첨 기록 /results

- 추첨 순서, 참가자 이름, 경품, 시각, 일반/연출 구분.
- 기록 CSV 내보내기.
- 기록 초기화는 별도 확인 후 수행.
- 초기 버전은 별도 페이지 대신 추첨 화면의 기록 패널로 시작 가능.
- 실제 참가자 명단이나 당첨 기록은 공개 저장소에 포함하지 않는다.

## 3. 룰렛 크기·확률·재고 규칙

- 기본 조각 확률 = 해당 등수의 남은 상품 개수 / 전체 남은 상품 개수.
- 예: 1등 1개·2등 3개·3등 6개 → 처음 확률 10%·30%·60%.
- 3등 당첨 후 1개·3개·5개 → 다음 확률 1/9·3/9·5/9, 조각 크기도 갱신.
- 조각 각도 = 해당 조각 확률 × 360도.
- 색상은 표시 속성이며 확률을 결정하지 않는다.
- 무작위 결과를 먼저 선정한 뒤, 해당 조각 내부에서 멈추는 회전 각도를 계산한다.
- 최종 포인터 위치와 기록된 결과가 항상 일치하도록 동일한 각도 계산을 사용한다.
- 조각 경계에 멈추지 않도록 내부 여유를 둔다.
- 회전 중에는 설정 변경, 중복 시작, 참가자 변경을 막는다.
- 재고는 등수별 상품 행 ID로 관리하며 상품명이나 색상을 키로 사용하지 않는다.
- 당첨 시 해당 행 재고 1개를 차감한다. 같은 상품명이 다른 등수에 있어도 서로 차감하지 않는다.
- 재고 소진 경품의 조각은 다음 추첨부터 제외하고 남은 상품 개수로 원판과 확률을 다시 계산한다.
- 소진 처리는 현재 회전이 끝난 뒤 적용하며 회전 도중 원판 구성을 바꾸지 않는다.
- 남은 조각이 하나면 유일한 경품임을 안내하고 진행하며, 없으면 추첨을 종료한다.
- 일반 추첨은 브라우저의 보안 난수 기능을 사용하는 방향으로 계획한다.
- 클라이언트 전용 첫 버전은 독립적인 서버 추첨 감사 기능까지 보장하는 범위가 아니다.

## 4. 카메라 모션 인식과 화면 피드백

운영자가 시작 방식을 선택한다: '동작 따라 하기' 또는 '룰렛 돌리기'.
두 방식은 같은 추첨 상태 흐름으로 연결하며 단순히 사람이 움직였다는 이유로 시작하지 않는다.

### A. 동작 따라 하기

- 화면에 짧은 반복 애니메이션과 문장으로 목표 동작 표시.
- 첫 동작 후보는 '양손을 머리 위로 올리기'. 화면 예시는 '양손을 들어 게이지를 채워 주세요!'.
- 카메라 위에 팔/손 위치와 목표 윤곽을 겹쳐 표시하여 현재 자세를 스스로 확인 가능.
- 자세 조건이 일정 시간 유지되면 진행 게이지가 차고 완료 시 시작.
- 유지 시간은 약 1초를 초기 튜닝값으로 두고 실제 장치 실험으로 확정.
- 순간적으로 비슷한 자세를 지나가는 것만으로는 완료 처리하지 않음.
- 신뢰도가 낮거나 손이 화면 밖이면 게이지를 중지하고 구체적인 안내 표시.
- 손 흔들기 등 추가 안내 동작은 검증 후 확장. 임의의 춤/동작을 모두 인식하는 기능은 첫 버전 범위가 아님.

### B. 룰렛 돌리는 동작

- 화면에 가상의 원과 회전 화살표를 표시.
- '손을 원에 올리고 화살표를 따라 크게 돌려 주세요!'라고 안내.
- 손이 시작 영역에 잠시 머무르면 준비 상태로 진입.
- 선택한 한 손의 이동 경로가 안내 원을 따라 충분한 원호를 그리면 회전 시작.
- 초기 기준은 반 바퀴 정도의 원호이며 실제 인식 실험으로 크기·시간·방향 허용치를 조정.
- 단순 좌우 왕복, 손 위치 흔들림, 원의 중심을 가로지르는 이동은 원호 완성으로 처리하지 않음.
- 진행 호와 손 궤적을 표시하여 얼마나 더 돌려야 하는지 전달.
- 인식된 손의 회전 방향으로 룰렛이 이어 돌아가는 연출을 목표로 함.
- 손의 속도는 시각적인 초기 회전 강도에만 반영하고 범위를 제한.
- 손을 계속 돌릴 필요 없이 동작 완성 후 룰렛이 자동 회전·감속·정지.
- 동작의 속도·크기·방향은 일반 추첨의 당첨 확률을 바꾸지 않음.

### C. 공통 인식 상태와 보호 장치

- 상태: 카메라 준비 → 참가자 찾기 → 동작 준비 → 인식 중 → 성공 → 회전 → 결과.
- 참가자에게 '손을 보여 주세요 / 조금 뒤로 이동해 주세요 / 동작을 유지해 주세요 / 성공!' 등 상태별 안내.
- 거울 화면과 안내 화살표, 인식 좌표의 방향을 일치시킨다.
- 활성 참가자 한 명과 선택한 손을 고정하여 다른 사람/반대 손으로 추적이 바뀌면서 동작이 완성되지 않게 한다.
- 여러 사람이 들어오거나 추적이 끊기면 진행을 중지하고 재준비를 안내.
- 준비 상태에서만 동작을 받고 회전·결과 화면의 움직임은 추가 추첨으로 이어지지 않게 한다.
- 인식 성공과 동시에 시작 입력을 잠가 한 동작에 한 회차만 실행.
- 다음 참가자 전환과 새 동작 준비를 마쳐야 다시 인식 가능.
- 참가자가 없거나 상품이 소진된 경우 모션으로 시작할 수 없음.
- 얼굴 식별은 범위에 포함하지 않는다.
- 영상은 기기 안에서 처리하고 녹화·업로드하지 않는 구조를 목표로 한다.
- 카메라 거부, 장치 없음, 다른 앱 사용 중, 어두움/인식 실패를 안내.
- 마우스·터치·키보드 시작을 대체 입력으로 제공하여 동작 수행이 어려운 참가자도 진행 가능.
- 페이지를 떠나면 카메라 사용을 종료.
- 손/상체 인식 기술은 기술 실험 후 선정하며 실제 구현 시 최신 공식 문서를 확인.

## 5. 1등 당첨 연출

- 설계 화면에서 연출 모드와 1등 경품을 준비.
- 추첨 화면의 지정 영역 길게 누르기 또는 운영자 단축키로 다음 회차 연출 예약.
- 운영자는 예약 상태를 확인하고 취소할 수 있음.
- 다음 시작 시 1등 조각으로 정지하도록 목표 각도를 설정.
- 빠른 회전, 긴 감속, 당첨 직전 긴장감, 축하 효과를 연출.
- 결과가 결정된 뒤 이미 도는 회차의 결과를 중간에 바꾸지는 않음.
- 1회 적용 후 예약은 자동 해제.
- 1등 미설정 또는 재고 소진 상태에서는 예약 불가.
- 연출 모드 사용 여부를 진행 화면에 표시하고 기록에도 남김.
- 일반 추첨 모드에서는 연출 예약 기능을 비활성화.
- 숨겨진 버튼은 화면을 간결하게 하는 운영 UI이며 인증/보안 수단으로 취급하지 않음.

## 6. 저장과 복구

- 설계 설정을 자동 저장하고 JSON 내보내기/불러오기 제공.
- 파일 형식 버전과 입력값을 검증하고 잘못된 파일은 기존 설정을 덮어쓰지 않음.
- 추첨 기록과 경품 재고를 함께 저장.
- 새로고침으로 회전 애니메이션이 중단된 경우 같은 추첨 ID로 결과를 복구.
- 중단 복구 과정에서 새 결과를 뽑거나 재고를 다시 차감하지 않음.
- 이름과 기록은 현재 기기 브라우저에 저장되며 다른 기기에 자동 동기화되지 않음을 안내.
- 저장 공간 오류 시 운영자에게 알리고 기록 내보내기 경로 제공.

## 7. 구현 단계와 예정 파일

아래 경로는 신규 구현 시 사용할 예정이며 아직 존재하는 앱 파일이 아니다.
기술 스택은 화면 초안 이후 확정한다. 화면·계산·모션 입력은 분리한다.

1. 화면 초안
   - docs/wireframes.md
   - 설계/추첨/결과의 PC·모바일 배치와 대표 예시 결정.
2. 룰렛 계산과 기본 화면
   - src/domain/roulette.*, src/domain/inventory.*
   - src/pages/SetupPage.*, src/components/RouletteWheel.*
   - 상품 개수 기반 각도·확률, 등수별 입력, 실시간 미리보기, 저장.
3. 수동 추첨 완성
   - src/pages/DrawPage.*, src/domain/draw-session.*
   - 참가자 입력, 회전, 감속, 결과, 재고, 중복 방지, 중단 복구.
4. 카메라 기술 실험 및 연결
   - docs/motion-spike.md, src/motion/*
   - 안내 동작 유지와 원호 돌리기 인식, 거울 좌표, 인식 오버레이를 실제 카메라로 실험.
   - 두 입력 방식의 성공률·오작동·성능을 검증한 뒤 공통 추첨 흐름에 연결.
5. 연출과 기록
   - src/pages/ResultsPage.*, src/domain/rehearsal.*
   - 1등 연출 예약/해제, 효과음, 축하 효과, CSV.
6. 현장 검증과 배포 준비
   - docs/verification.md
   - PC/모바일/프로젝터, 카메라 권한 실패, 긴 이름, 재고 소진, 새로고침 확인.
   - 호스팅과 실제 배포는 별도 구현 단계에서 다룸.

처음 구현할 최소 흐름:
경품 편집 → 이름 입력 → 수동으로 회전 → 정확한 경품 정지 → 결과 기록.
이 흐름을 먼저 검증하고 모션을 연결한다.

## 8. 완료 판정과 검증

- 상품 개수 1:3:6의 세 조각이 각도 36/108/216도와 확률 10/30/60%로 자동 표시됨.
- 3등 1회 당첨 후 남은 개수 1:3:5에 맞춰 다음 원판이 재구성됨.
- 총 10개 상품은 10회 지급 뒤 재고 0으로 종료되며 11회차 시작 불가.
- 색상을 바꾸어도 확률과 경품 식별자가 바뀌지 않음.
- 같은 상품명을 가진 서로 다른 등수의 재고는 독립되며 당첨된 행에서만 1개 차감됨.
- 다양한 목표 각도와 조각 경계 주변에서 포인터와 결과가 일치함.
- 회전 중 반복 클릭/모션 입력에도 추첨·기록·재고 반영은 한 번.
- 카메라 미허용 상태에서도 수동 추첨을 끝까지 수행 가능.
- 동작 안내와 손/팔 위치, 진행 게이지가 카메라 화면에 표시됨.
- 안내 자세를 정해진 시간 유지하면 시작하고 잠깐 스쳐 간 자세에는 시작하지 않음.
- 돌리기 모드에서 시작 영역 진입 후 원호 완성 시 한 회차만 시작.
- 좌우 흔들기나 중심 가로지르기에는 돌리기 완료가 발생하지 않음.
- 거울 화면의 손 움직임·화살표·원판 회전 방향이 일치.
- 추적 끊김과 다른 사람 진입 시 진행이 멈추고 재준비 전에는 시작하지 않음.
- 동작 한 번으로 한 회차만 시작하고 결과 후 재준비 전에는 재시작되지 않음.
- 두 모드 각각 실제 카메라에서 유효 동작 20회 중 18회 이상 시작을 초기 목표로 검증.
- 모드별 정지 배경 1분과 비목표 동작 20회에서 오시작 0회를 초기 목표로 검증.
- 밝은 환경/어두운 환경, 앉은 자세/선 자세에서 측정 조건과 결과를 기록.
- 모션 목표 미달 시 민감도/입력 방식을 조정하고 실측 조건과 결과를 기록.
- 1등 연출은 예약된 한 회차에만 적용되고 일반 추첨과 기록으로 구분됨.
- 1등 재고 소진 시 연출 예약 불가.
- 회전 중 새로고침해도 결과가 바뀌거나 재고가 중복 차감되지 않음.
- 잘못된 설정 파일을 불러와도 기존 설정 보존.
- 모바일 세로 화면과 PC 전체 화면에서 조작 버튼과 결과를 읽고 사용할 수 있음.
- 단위 검증은 각도/확률/재고/상태 전이에 집중하고 화면 흐름은 브라우저로 확인.
- 카메라와 현장 환경은 실제 장치 검증 여부를 별도로 명시.
