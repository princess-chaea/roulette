# 실제 카메라 연결판 검증 기록

2026-11-09 · 로컬 Chrome/Chromium, Node.js. 공개 배포와 실물 카메라 인식률 측정은 미실시.

## 통과한 검증

- `node --check` 앱·카메라·모션·룰렛 JavaScript 구문 검증.
- `node --test tests/*.cjs`: 30개 통과. 카메라 수명 주기 5개, 동작 판정 15개, 룰렛 계산 7개, 표시 규칙 3개.
- 권한 요청 취소 뒤 도착한 스트림 해제, 이전 모델의 뒤늦은 성공/실패 격리, 트랙/RAF 해제, 추론 실패 후 새 모델로 재연결.
- 양손 자세 1초 유지와 원호 양방향 완성, 추적 끊김·직선/중심 통과·역방향·손 교체·모드 전환 초기화.
- 실제 자체 호스팅 MediaPipe Tasks Vision 1.2.2와 Lite 모델 로딩 후 640×480 가상 카메라 프레임 분석. 사람 없는 영상에서 당첨 시작 없음.
- 별도의 브라우저 SDK 출력 좌표 재생에서 실제 GestureDetector와 앱을 통과해 두 동작 모두 자동 추첨·재고 1개 차감·기록 1건을 확인. 재준비 없이 반복 시작 없음.
- 이름 입력칸 없음, SchoolPoster/KERISBaeum 폰트 로딩 확인.
- 기록 창 열기와 카메라 중지는 인식 종료. 설계 화면 이동 후 카메라 트랙 종료 확인.
- 확대창이 보이는 동안 당첨 결과 비공개, 정지 후 원판 포인터와 저장한 착지 각도 오차 0.001도 이내, 총 재고 20→19·기록 0→1 확인.
- 320/390/768/1024/1440px의 두 화면, 총 10개 배치에서 가로 넘침 없음. PC·모바일 캡처를 열어 폰트·로고·선물 목록·안내 그림 확인.

## 로그와 한계

MediaPipe가 CPU XNNPACK 준비 INFO를 stderr로 출력하여 브라우저 콘솔에서는 error로 분류됐고, OpenGL/feedback 관련 경고 3건이 있었다. 이 로그 뒤 모델 분석이 계속 작동했으며 앱 예외나 모델 초기화 실패는 없었다.

실물 카메라·어린이/성인·다른 조명·촬영 거리·프로젝터·Safari·모바일 실기기의 성공률과 지연은 아직 측정하지 않았다. 실제 모델 실행, 합성 좌표 판정, 물리 동작 인식률은 서로 다른 검증 범위다. 전체 접근성 감사와 여러 창 재고 동기화도 후속 범위다.

실제 카메라 화면은 HTTPS/localhost에서 사용한다. file:// 단일 미리보기는 UI 확인용이며 카메라 연결 시 실행 안내를 표시한다. 공개 호스팅·백엔드/DB·1등 연출·내보내기·사운드는 미구현이다.

## 최신 변경 재검증

- 관절 좌표 재생으로 상체 중앙 2초 전에는 안내가 시작되지 않음, 양손 자세만으로는 추첨하지 않음, 이후 원호를 완성해야 재고 1개 차감·기록 1건이 발생함을 확인. 골반 점은 낮은 신뢰도로 제거한 좌표를 사용했다.
- 동작 인식 시작 버튼과 이름 입력 없음. 결과에는 회차 축하 문구 없이 새싹 이미지와 확인 버튼. 확인 후 2초 위치 확인으로 복귀.
- 확대창의 실제 위치가 원래 상단 포인터를 덮음을 브라우저 좌표로 확인. 17개 각도 표본에서 양·음 회전 변화가 모두 측정되어 작은 좌우 정착을 확인. 확대 후 추가 한 바퀴 회전 없음.
- 최종 원판 경계·선택 조각 안쪽의 정지 각도와 단일 상품의 가짜 경계 흔들림 생략은 단위 테스트로 검증.
- 최신 10개 반응형 배치와 로고 배경 제거·중앙 아이콘 제거·하단 저작권·제작자·결과 팝업을 재확인.

## 시작 자세와 등수별 이미지

- 네 시작 자세의 유효 모양·1초 유지와 서로 다른 자세의 오인식 방지를 합성 좌표로 검증. 팔 하트는 손목 근접·머리 위 위치·벌어진 팔꿈치를 함께 확인한다.
- 시작 자세 순환과 1~10등 별도 이미지/11등 이상 10등 대체 규칙을 단위 테스트로 확인했다. PNG 10장을 브라우저에서 모두 로딩하고 표정·소품·동작을 한 화면으로 시각 확인했다.
- 실물 카메라의 네 자세별 성공률은 아직 측정하지 않았다.

브라우저 최종 연결 검증: 네 자세가 hands_up → arms_out → one_hand_up → arm_heart 순서로 실제 앱에 안내되고, 합성 관절 좌표에서 매번 자세 다음 원호를 완성해야 회차가 1회씩 확정됐다. 4회차 연결과 11등 당첨 복구 시 rank-10.png 로딩을 확인했다.


## 카메라 피드백 후 조정

- 양팔 벌리기는 골반 추정 높이 대신 어깨 간격을 기준으로 허용 범위를 계산하여 조금 낮거나 구부러진 팔도 인정한다.
- 원 그리기는 AR 손잡이에 250ms 멈추어 잡은 뒤 같은 손을 약 60도 넓게 움직이면 완료한다. 반대 팔과 팔꿈치는 요구하지 않는다. 손 떨림·중심 가로지르기·다른 손으로 바꾸기는 완료로 세지 않는다.
- 손잡이를 잡은 뒤 원판이 손의 방향을 따라 미리 움직이며, 성공 시 그 각도에서 본 회전으로 연결된다. 확률은 바뀌지 않는다.
- 확대창은 접근 회전 종료 1100ms 전에 나타나 650ms 동안 커진다. 원판과 동일한 애니메이션 시계를 사용해 감속과 좌우 정착이 연속으로 보인다.
- 800px 이하 화면에서는 모션 완료 시 룰렛 영역으로 자연스럽게 스크롤한다.
- 추첨 화면 하단의 설계 화면 이동 링크는 삭제하고 상단 탭을 사용한다.

검증: Node 테스트 41개 통과. 최신 브라우저에서 네 시작 자세→손잡이→추첨 4회차와 11등 이미지 대체를 확인했다. 확대 시작은 회전 시작 후 약3033ms였고 확대 중에도 약19.79도 이동했으며, 원판과 확대창 각도 오차는0.001도 미만이었다. 실물 카메라의 새 기준 체감 인식률은 사용자 테스트 대상이며 자동 검증에는 합성 관절 좌표를 사용했다. Vercel 배포 오류는 사용자가 해결되었다고 확인하여 추가 배포 설정을 변경하지 않았다.

추가 브라우저 검증: 390px 화면에서 한 손 손잡이를 25도 움직일 때 미리보기만 회전하고, 이어서 약60도에 도달하면 추첨과 룰렛 자동 스크롤이 시작됐다. 네 자세 4회차와 재고 한 번 차감을 확인했다. 분리 창에서 기존 영상이 계속 진행되고, 안내 문구 동기화·카메라 연결/종료·양쪽 전체화면·창 닫기 후 배치 복구를 확인했다. 실물 듀얼 모니터 배치와 실물 카메라 성공률은 미측정이다. MediaPipe의 XNNPACK delegate 생성 INFO가 console.error 채널로 나오는 것은 모델 오류가 아니며 인식 엔진은 실행됐다.


운영자 1등 모드: 연구회 로고·명칭 영역을 0.9초 이내 간격으로 연속 5번 누르면 배경이 옅은 붉은색으로 바뀐다. 활성 상태에서 한 번 더 누르면 취소된다. 실제 다음 추첨 한 회차에만 남아 있는 1등 상품을 선택하고 즉시 모드를 해제하며, 기존 감속·경계 확대·결과·재고 처리 경로를 그대로 사용한다. 1등 소진 시 활성화하지 않는다. 회전 중 클릭은 무시하며 새로고침하면 모드는 해제된다. 일반 모드의 수량 비례 추첨은 유지한다.

운영자 모드 브라우저 검증: 4회 클릭 미활성·5회 활성·추가1회 취소·다시5회 활성·다음1회 1등·재고1회차감·모드자동해제·1등 소진 후 재활성차단·일반 확률 선택 복귀를 확인했다.


## 최신 변경: 결과 동기화·모바일 상단·하트·한 바퀴

기존 약60도 시작 기준은 폐기하고 중앙 시작점에서 한 바퀴(360도) 완료로 변경했다. 단위 테스트41개로 양방향 완주·부분 원 미완료·불규칙한 반경·역회전·손 교체·중심 가로지르기 및 하트 높이/골반 가림 변화를 확인했다. 브라우저에서는 회전 중 카메라 새 창에 결과가 아직 없고, 멈춘 뒤 동일한 이미지·등수·상품명이 표시됨을 확인했다. 새 창 확인 버튼으로 양쪽 결과창이 함께 닫혔다. 전체화면 새 창에서도 동일하게 동작한다. 모바일 320/360/390/430/600/800px에서 상단 브랜드와 연구회명이 같은 줄이고 서로 겹치거나 가로로 넘치지 않음을 확인했다. 실물 카메라 성공률 및 실제 듀얼 모니터 배치는 미측정이다.

최신 전체 흐름 검증: 390px에서 네 시작 자세를 차례로 수행한 뒤 중앙 손잡이의 부분 회전은 미리보기만 움직였고, 360도 완주 후 추첨과 자동 스크롤이 시작됐다. 4회차마다 정확히 한 번 재고가 차감되고 11등 이미지 대체도 유지됐다. 합성 관절 좌표를 사용한 브라우저 검증이다.
